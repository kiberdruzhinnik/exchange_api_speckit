# Research: CBR Currency Rates API

## Official source and rate mapping

- **Decision**: Use the Bank of Russia's public XML interface. Read currency IDs and ISO codes from `XML_valFull.asp`, then intersect them with the codes in the current `XML_daily.asp` publication to validate current support. Cache that supported directory for 60 seconds. Fetch the entire source-available date range for the internal ID, from its earliest available rate through the latest published date, from `XML_dynamic.asp`; fetch the latest official rate from `XML_daily.asp` on every quote request.
- **Rationale**: The official interface documents the currency directory, dated daily rates, and date-range history in one public service. The directory supports dynamic validation of any currently supported currency without a hard-coded USD/EUR/CNY list. The historical response provides a source nominal and value; dividing the value by the nominal yields RUB per one requested unit.
- **Mapping**: Set `date` from the source effective date at UTC midnight; when both source `Value` and `Nominal` are present, set `close = Value / Nominal`; set `facevalue = Nominal` when provided. For a source field that is absent, serialize the corresponding API value as null; if Value or Nominal is absent, `close` is null because the per-unit value cannot be calculated. CBR has no daily OHLC or traded-volume data, so `high`, `low`, and `volume` are null. Reject non-positive provided nominals, non-finite or non-positive computed rates, invalid dates, duplicate dates, and malformed/unusable documents as dependency failures.
- **Directory freshness**: Cache the supported-currency directory in process for exactly 60 seconds, then fetch it again. This avoids an extra directory lookup on every request while bounding how long removed or added currencies can remain stale. The directory cache never stores currency-rate data; every quote request fetches the latest rate anew. History responses use the persistent history cache specified by the feature.
- **Live endpoint finding**: `XML_val.asp?d=0` omits `ISO_Char_Code`, while `XML_valFull.asp` includes it and includes legacy entries. Intersecting the full directory with the current daily publication provides stable CBR IDs while excluding entries without a current daily rate. `XML_daily.asp?d=0` returns the current publication and is used only for directory support validation; quote requests make a distinct uncached request to `XML_daily.asp`.
- **Alternatives considered**: Hard-coding common currencies was rejected because the spec accepts any CBR-supported currency. A non-CBR market-data provider was rejected because the feature requires official Bank of Russia rates. The CBR daily-data SOAP service also provides one-unit rates (`VunitRate`) and full currency metadata, but the simple documented XML endpoints cover the needed directory, daily quote, and historical dynamic operations with a smaller integration surface.
- **References**: [Bank of Russia XML interface](https://www.cbr.ru/development/SXML/); [Bank of Russia daily data service](https://www.cbr.ru/development/DWS/).

## Rust service integration and persistence

- **Decision**: Add `src/cbr/` parallel to `src/moex/` and `src/spbex/`; add the CBR client to `AppState` and construct it from `AppConfig`; add `/v1/cbr/{symbol}` and `/v1/cbr/{symbol}/quote` handlers in the shared router. Reuse `DailyMarketRecord`, `LatestTradeRecord`, `HistoryCache`, and `CacheStore`. Use `CBR:{SYMBOL}` as the history key. Persist only validated history payloads. Quote never reads or writes either cache layer.
- **Rationale**: Existing shared records already serialize the exact six-field contract, including nullable fields and UTC `Z` dates. Shared cache components implement TTL, singleflight behavior, and SQLite persistence across restarts. Exchange-qualified keys avoid collisions with symbols that appear on multiple exchanges.
- **Alternatives considered**: A separate CBR service or database would duplicate the existing service boundary and persistence behavior. A generic exchange adapter refactor is not needed to add one independent source integration.
- **Configuration**: Add `CBR_API_BASE_URL` (default `https://www.cbr.ru/`) and `CBR_MAX_RESPONSE_BYTES`; reuse the existing upstream timeout and history-cache TTL, capacity, and database path. Document all new settings and defaults.

## Error and input handling

- **Decision**: Trim and uppercase the path symbol; accept the project's established ASCII ticker syntax, then verify it against the current CBR daily-currency directory by ISO character code. Return HTTP 400 for malformed or unsupported codes, HTTP 502 for transport/status/oversized/XML/invalid-rate failures, and HTTP 503 for history-store failures. A valid successful empty history returns `[]`; an empty latest-rate result returns one six-field all-null record.
- **Rationale**: This preserves the documented spec outcomes and distinguishes invalid client input, unavailable source data, valid absence of data, and persistence failure.
- **Alternatives considered**: Treating an empty response as unsupported is unreliable because the service does not expose a separate symbol catalog beyond its supported currency directory. Returning errors for absent quote data contradicts the specified nullable response.

## Validation and delivery

- **Decision**: Use representative XML fixtures for currencies, nominal values (including non-unit nominal), full history, empty data, and malformed data; test client status/size bounds, mapping, supported-symbol validation, route behavior, cache persistence/restart, uncached quote requests, and OpenAPI schemas. Benchmark the local release binary against production `www.cbr.ru` using 10 concurrent clients and a fixed 10 total requests/second arrival rate for history-only, quote-only, and combined profiles. Build the Docker image successfully for `linux/amd64` (no amd64 runtime test is required), preserve `linux/arm64` support, and validate the shared SIGINT shutdown behavior: stop accepting requests, drain in-flight work, and cancel remaining work at 30 seconds. Run the required final Semgrep and Trivy scans.
- **Rationale**: Fixtures make results stable despite changing official rates. Live latency measurements verify the shared hard service-level gate with the actual source and compiled binary. SIGINT and amd64 acceptance reuse the existing service-wide behavior: bounded graceful drain/cancellation and successful amd64 image build only. Container validation follows the existing multi-architecture distroless workflow.
- **Acceptance handling**: Consume complete response bodies, report actual scheduled/issued/skipped requests, successes, errors, and successful-response p95 per route. Runs below 10 requests/second or with skipped arrivals are invalid. If any valid profile misses the one-second p95 target, optimize and repeat; the feature remains incomplete until all valid profiles pass.
